HTTP 协议

HTTP 是前端与后端通信的基石——掌握请求方法、状态码、缓存策略和 HTTP/2 特性，是构建高性能 Web 应用的前提。

1. 核心概念与定义

HTTP（HyperText Transfer Protocol）是应用层协议，用于客户端（浏览器）和服务器之间传输超文本数据。它是无状态协议（每次请求独立），基于请求-响应模型。

HTTP 经历了多个版本演进：HTTP/1.0（短连接）、HTTP/1.1（长连接、管线化）、HTTP/2（多路复用、头部压缩）、HTTP/3（基于 QUIC/UDP）。每个版本都解决了前代的性能瓶颈。

前端开发者需要重点关注：请求方法与语义、状态码含义、缓存策略（强缓存 + 协商缓存）、HTTPS 安全、以及 HTTP/2 对前端优化的影响。

2. 关键特性与工作原理

2.1 HTTP 请求方法

方法语义幂等安全请求体
GET获取资源是是无
POST创建资源否否有
PUT全量更新资源是否有
PATCH部分更新资源否否有
DELETE删除资源是否可选
HEAD获取响应头是是无
OPTIONS预检请求（CORS）是是无

幂等：多次请求效果等同于一次。安全：不修改服务器资源。

2.2 HTTP 状态码

范围类别常见状态码
1xx信息性100 Continue
2xx成功200 OK、201 Created、204 No Content
3xx重定向301 永久重定向、302 临时重定向、304 Not Modified、307/308
4xx客户端错误400 Bad Request、401 Unauthorized、403 Forbidden、404 Not Found、405 Method Not Allowed
5xx服务器错误500 Internal Server Error、502 Bad Gateway、503 Service Unavailable、504 Gateway Timeout

2.3 HTTP 缓存策略

缓存类型相关头部机制
强缓存Cache-Control: max-age=3600在有效期内直接使用缓存，不发请求
Expires: Thu, 01 Dec 2026 ...HTTP/1.0 方式，绝对时间（已过时）
Cache-Control: no-cache/no-storeno-cache 跳过强缓存、no-store 完全不缓存
协商缓存Last-Modified / If-Modified-Since基于修改时间，精确到秒
ETag / If-None-Match基于内容哈希，更精确
 
text缓存判断流程：
  1. 检查 Cache-Control / Expires → 命中强缓存 → 200 (from cache)
  2. 未命中强缓存 → 发请求携带 If-Modified-Since / If-None-Match
  3. 服务器比对 → 未修改 → 304 Not Modified → 使用缓存
  4. 服务器比对 → 已修改 → 200 OK + 新资源

2.4 HTTP/2 核心特性

特性说明前端影响
多路复用一个 TCP 连接并行多个请求/响应不再需要域名分片、合并文件
头部压缩HPACK 算法压缩请求头减少头部开销
服务器推送服务器主动推送资源可预推送关键资源
流优先级设置请求权重关键资源优先加载

3. 代码示例与最佳实践

示例一：fetch 请求封装

JavaScript/**
 * 封装 fetch，统一处理错误、超时、响应格式
 */
async function request(url, options = {}) {
  const {
    timeout = 10000,
    headers = {},
    ...rest
  } = options;

  const controller = new AbortController();
  const timeoutId = setTimeout(() => controller.abort(), timeout);

  try {
    const response = await fetch(url, {
      ...rest,
      headers: {
        'Content-Type': 'application/json',
        ...headers,
      },
      signal: controller.signal,
    });

    clearTimeout(timeoutId);

    if (!response.ok) {
      throw new Error(`HTTP ${response.status}: ${response.statusText}`);
    }

    // 根据响应类型解析
    const contentType = response.headers.get('content-type');
    if (contentType?.includes('application/json')) {
      return await response.json();
    }
    return await response.text();
  } catch (error) {
    clearTimeout(timeoutId);
    if (error.name === 'AbortError') {
      throw new Error(`请求超时 (${timeout}ms)`);
    }
    throw error;
  }
}

// 使用
const users = await request('/api/users');
const newUser = await request('/api/users', {
  method: 'POST',
  body: JSON.stringify({ name: 'Alice' }),
});

示例三：文件上传与进度

JavaScript/**
 * 带进度回调的文件上传
 */
function uploadFile(file, { onProgress, onSuccess, onError }) {
  const xhr = new XMLHttpRequest();
  const formData = new FormData();
  formData.append('file', file);

  // 上传进度
  xhr.upload.addEventListener('progress', (e) => {
    if (e.lengthComputable) {
      const percent = Math.round((e.loaded / e.total) * 100);
      onProgress?.(percent);
    }
  });

  xhr.addEventListener('load', () => {
    if (xhr.status >= 200 && xhr.status < 300) {
      onSuccess?.(JSON.parse(xhr.responseText));
    } else {
      onError?.(new Error(`Upload failed: ${xhr.status}`));
    }
  });

  xhr.addEventListener('error', () => onError?.(new Error('Network error')));
  xhr.open('POST', '/api/upload');
  xhr.send(formData);

  return xhr; // 可用于取消上传
}

// 使用
const xhr = uploadFile(file, {
  onProgress: (percent) => console.log(`${percent}%`),
  onSuccess: (data) => console.log('上传成功:', data),
  onError: (err) => console.error('上传失败:', err),
});

示例四：请求重试与竞速

JavaScript// 请求重试（带指数退避）
async function fetchWithRetry(url, options = {}, retries = 3) {
  for (let i = 0; i <= retries; i++) {
    try {
      const response = await fetch(url, options);
      if (response.ok) return response;
      if (response.status >= 500 && i < retries) {
        const delay = Math.pow(2, i) * 1000 + Math.random() * 1000;
        await new Promise(r => setTimeout(r, delay));
        continue;
      }
      throw new Error(`HTTP ${response.status}`);
    } catch (error) {
      if (i === retries) throw error;
      await new Promise(r => setTimeout(r, Math.pow(2, i) * 1000));
    }
  }
}

// 请求竞速：最快的镜像源获胜
async function fetchFastest(urls, options) {
  return Promise.any(urls.map(url => fetch(url, options)));
}

// 使用：多 CDN 竞速
const response = await fetchFastest([
  'https://cdn1.example.com/data.json',
  'https://cdn2.example.com/data.json',
  'https://cdn3.example.com/data.json',
]);

示例五：请求取消与 AbortController

JavaScript// 场景：搜索框输入时，取消上一次请求
let searchController = null;

async function search(query) {
  // 取消上一次请求
  if (searchController) {
    searchController.abort();
  }
  
  searchController = new AbortController();
  const { signal } = searchController;
  
  try {
    const response = await fetch(`/api/search?q=${encodeURIComponent(query)}`, { signal });
    const data = await response.json();
    renderResults(data);
  } catch (error) {
    if (error.name === 'AbortError') {
      console.log('请求已取消'); // 正常行为，不报错
    } else {
      console.error('搜索失败:', error);
    }
  } finally {
    searchController = null;
  }
}

// 配合防抖使用

4. 常见问题与坑点

GET 和 POST 的本质区别是什么？ +

语义不同：GET 获取资源，POST 提交数据。技术上的区别：① GET 参数在 URL 中，POST 在请求体中；② GET 可缓存、可收藏、有长度限制（浏览器限制），POST 默认不缓存；③ GET 幂等安全，POST 不幂等不安全。但 HTTP 规范并未禁止 GET 有请求体或 POST 有 URL 参数。

301 和 302 的区别？对 SEO 的影响？ +

301 永久重定向：搜索引擎会将权重转移到新 URL，旧 URL 从索引中移除。302 临时重定向：搜索引擎仍索引旧 URL。前端注意：301 会被浏览器缓存，后续请求直接跳转；302 每次都会先请求原 URL。

HTTP/2 为什么不需要雪碧图和域名分片？ +

HTTP/1.1 的浏览器限制每个域名最多 6 个 TCP 连接，所以用域名分片增加连接数。HTTP/2 在一个 TCP 连接上多路复用，无限并发请求。雪碧图、合并 JS/CSS 等优化在 HTTP/2 下反而可能有害（缓存粒度变大）。

🚫 混合内容：HTTPS 页面不能加载 HTTP 资源

HTTPS 页面中加载 HTTP 脚本、图片、iframe 等会被浏览器阻止（混合内容限制）。解决方案：全部使用 HTTPS；使用协议相对 URL（//cdn.example.com/script.js）；设置 upgrade-insecure-requests 头。

⚠ Cache-Control: no-cache 不等于不缓存

no-cache 意为"不直接使用缓存，每次都要协商验证"，仍会缓存并可能返回 304。真正的"不缓存"是 no-store。命名有误导性，面试高频考点。

1HTTP 缓存机制是怎样的？强缓存和协商缓存的区别？
强缓存：Cache-Control/Expires 有效期内直接使用缓存，不发请求，返回 200 (from cache)。协商缓存：带 If-Modified-Since/If-None-Match 请求，服务器判断是否修改，未修改返回 304。优先级：Cache-Control > Expires > ETag > Last-Modified。
2HTTP/1.1、HTTP/2、HTTP/3 有什么区别？
HTTP/1.1：文本协议、队头阻塞、每个域名 6 个连接。HTTP/2：二进制帧、多路复用（解决应用层队头阻塞）、头部压缩 HPACK、服务器推送。HTTP/3：基于 QUIC（UDP），解决 TCP 层队头阻塞，0-RTT 连接，更好的移动端切换。
3如何取消一个已发送的 HTTP 请求？
使用 AbortController：创建 controller，将 signal 传入 fetch 的 options，调用 controller.abort() 取消请求。fetch 会抛出 AbortError。XHR 用 xhr.abort()。注意：abort 后服务端可能已收到请求，只是客户端忽略响应。
