触摸与手势事件

移动端交互的核心是触摸——理解 touch 事件、手势识别和 300ms 延迟，才能构建流畅的移动端体验。

1. 核心概念与定义

移动端浏览器通过Touch 事件处理触摸交互。与鼠标事件不同，Touch 事件支持多点触控，每个触摸点有独立的标识。手势（如滑动、缩放、旋转）是通过分析 Touch 事件序列来识别的。

移动端还有两个特殊问题：300ms 点击延迟（浏览器等待判断是否双击缩放）和click 延迟穿透（touch 事件先触发，click 延迟 300ms 后触发）。

2. 关键特性与工作原理

2.1 Touch 事件类型

事件触发时机典型用途
touchstart手指触摸屏幕记录起始位置
touchmove手指在屏幕上移动滑动、拖拽
touchend手指离开屏幕判断手势结果
touchcancel触摸被系统中断（来电等）清理状态

2.2 Touch 对象属性

属性说明
identifier触摸点唯一标识
clientX / clientY视口坐标
pageX / pageY页面坐标（含滚动）
screenX / screenY屏幕坐标
target触摸的 DOM 元素

通过 event.touches（所有触摸点）、event.targetTouches（当前元素的触摸点）、event.changedTouches（变化的触摸点）访问 Touch 对象列表。

2.3 事件触发顺序

text">触摸操作：touchstart → touchmove(多次) → touchend
之后（约300ms）：click

滑动操作：touchstart → touchmove(多次) → touchend
不会触发 click（因为移动了）

多指操作：
touchstart(第1指) → touchstart(第2指) → touchmove → touchend

2.4 passive 事件监听器

Chrome 为了优化滚动性能，默认将 touchstart/touchmove 监听器设为 passive（不可调用 preventDefault）。如果需要阻止默认行为，必须显式设为 { passive: false }。

3. 代码示例与最佳实践

示例一：滑动方向检测

JavaScript/**
 * 检测滑动手势
 */
function useSwipe(element, options = {}) {
  const { threshold = 50, onSwipeLeft, onSwipeRight, onSwipeUp, onSwipeDown } = options;
  let startX, startY;

  element.addEventListener('touchstart', (e) => {
    const touch = e.touches[0];
    startX = touch.clientX;
    startY = touch.clientY;
  }, { passive: true });

  element.addEventListener('touchend', (e) => {
    const touch = e.changedTouches[0];
    const dx = touch.clientX - startX;
    const dy = touch.clientY - startY;

    // 判断主方向和距离
    if (Math.abs(dx) > Math.abs(dy)) {
      if (Math.abs(dx) > threshold) {
        dx > 0 ? onSwipeRight?.() : onSwipeLeft?.();
      }
    } else {
      if (Math.abs(dy) > threshold) {
        dy > 0 ? onSwipeDown?.() : onSwipeUp?.();
      }
    }
  }, { passive: true });
}

// 使用
useSwipe(carousel, {
  threshold: 30,
  onSwipeLeft: () => nextSlide(),
  onSwipeRight: () => prevSlide(),
});

示例二：双指缩放

JavaScript/**
 * 双指缩放手势
 */
function onPinch(element, callback) {
  let initialDistance = 0;
  let currentScale = 1;

  function getDistance(touches) {
    const dx = touches[0].clientX - touches[1].clientX;
    const dy = touches[0].clientY - touches[1].clientY;
    return Math.sqrt(dx * dx + dy * dy);
  }

  element.addEventListener('touchstart', (e) => {
    if (e.touches.length === 2) {
      initialDistance = getDistance(e.touches);
    }
  }, { passive: true });

  element.addEventListener('touchmove', (e) => {
    if (e.touches.length === 2) {
      e.preventDefault(); // 阻止浏览器默认缩放
      const newDistance = getDistance(e.touches);
      const scale = newDistance / initialDistance;
      callback({ scale, delta: scale - currentScale });
      currentScale = scale;
    }
  }, { passive: false }); // 需要 preventDefault，不能 passive

  element.addEventListener('touchend', () => {
    currentScale = 1;
  }, { passive: true });
}

示例四：防止穿透点击

JavaScript/**
 * 点击穿透问题：
 * 点击弹窗关闭按钮 → touchend 关闭弹窗 → 300ms 后 click 触发在弹窗下面的元素上
 */

// 方案一：touchend 阻止默认行为
closeBtn.addEventListener('touchend', (e) => {
  e.preventDefault(); // 阻止后续 click 事件
  closeModal();
});

// 方案二：全部用 touch 事件替代 click
function addTapListener(element, handler) {
  let startX, startY, startTime;

  element.addEventListener('touchstart', (e) => {
    const touch = e.touches[0];
    startX = touch.clientX;
    startY = touch.clientY;
    startTime = Date.now();
  }, { passive: true });

  element.addEventListener('touchend', (e) => {
    const touch = e.changedTouches[0];
    const dx = Math.abs(touch.clientX - startX);
    const dy = Math.abs(touch.clientY - startY);
    const dt = Date.now() - startTime;

    // 判断为"点击"：位移小、时间短
    if (dx < 10 && dy < 10 && dt < 300) {
      e.preventDefault();
      handler(e);
    }
  }, { passive: false });
}

// 方案三：弹窗关闭后延迟 300ms 再移除 DOM
function closeModal() {
  modal.style.opacity = '0';
  setTimeout(() => modal.remove(), 300); // 等 click 事件触发后再移除
}

示例五：下拉刷新

JavaScript/**
 * 原生下拉刷新（CSS + Touch 事件）
 */
function setupPullRefresh(container, onRefresh) {
  let startY = 0;
  let pulling = false;
  const indicator = container.querySelector('.pull-indicator');

  container.addEventListener('touchstart', (e) => {
    if (container.scrollTop === 0) {
      startY = e.touches[0].clientY;
      pulling = true;
    }
  }, { passive: true });

  container.addEventListener('touchmove', (e) => {
    if (!pulling) return;
    const dy = e.touches[0].clientY - startY;
    if (dy > 0 && container.scrollTop === 0) {
      // 下拉中，移动指示器
      const distance = Math.min(dy * 0.5, 80); // 阻尼效果
      indicator.style.transform = `translateY(${distance}px)`;
      indicator.textContent = distance >= 60 ? '松开刷新' : '下拉刷新';
    }
  }, { passive: true });

  container.addEventListener('touchend', () => {
    if (!pulling) return;
    pulling = false;
    const distance = parseInt(indicator.style.transform.match(/\d+/)?.[0] || '0');
    if (distance >= 60) {
      indicator.textContent = '刷新中...';
      onRefresh().finally(() => {
        indicator.style.transform = 'translateY(0)';
      });
    } else {
      indicator.style.transform = 'translateY(0)';
    }
  }, { passive: true });
}

4. 常见问题与坑点

为什么 touchmove 中调用 preventDefault 没效果？ +

Chrome 默认将 touchmove 监听器设为 passive: true，此时 preventDefault 无效。需要显式设为 { passive: false }。但这样会影响滚动性能，请只在确实需要阻止默认行为时使用。

iOS 的 click 事件延迟怎么解决？ +

最简单方案：CSS touch-action: manipulation（允许平移和缩放，禁止双击缩放）。配合 viewport 的 user-scalable=no 彻底消除。现代浏览器已默认优化，大部分场景不再需要额外处理。

🚫 不要在 touchmove 中做重计算

touchmove 每帧触发（60fps 时约 16ms 一次），在其中做 DOM 操作或重计算会卡顿。使用 requestAnimationFrame 节流：记录最新位置，在 rAF 回调中更新 DOM。

1移动端 300ms 延迟的原因和解决方案？
原因：浏览器等待 300ms 判断用户是否要双击缩放。方案：① viewport 设 user-scalable=no；② CSS touch-action: manipulation；③ FastClick 库（已过时）。现代浏览器配合 viewport 已自动优化。
2如何实现自定义手势识别？
记录 touchstart 的位置和时间，在 touchmove/touchend 中分析：① 位移方向和距离→滑动；② 两指距离变化→缩放；③ 两指角度变化→旋转；④ 时间短+位移小→点击；⑤ 快速连续点击→双击/多击。
