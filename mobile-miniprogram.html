微信小程序开发

微信小程序有独特的双线程架构和组件体系——理解其运行机制和开发规范，是进入小程序开发领域的第一步。

1. 核心概念与定义

微信小程序是微信提供的轻量级应用形态，无需安装即可使用。它采用双线程模型：渲染层（WebView）和逻辑层（JsCore）分别运行在不同线程，通过 Native 层通信。

小程序的开发语言不是 HTML/CSS/JS，而是 WXML（模板）、WXSS（样式）、JS（逻辑）、JSON（配置）。虽然语法类似 Web，但底层机制完全不同。

2. 关键特性与工作原理

2.1 双线程模型

text┌──────────────────────────────────────────┐
│              微信客户端 (Native)           │
│  ┌──────────┐  WeixinJSBridge  ┌───────┐ │
│  │ 渲染层    │ ←─────────────→ │ 逻辑层 │ │
│  │ (WebView) │   数据通信       │ (JSCore)│ │
│  │ 多个页面   │                 │ 单实例  │ │
│  └──────────┘                  └───────┘ │
│        ↑                           ↑      │
│    WXML/WXSS                    JS       │
└──────────────────────────────────────────┘

优势：逻辑与渲染分离，JS 不会阻塞 UI
代价：通信有开销，不能直接操作 DOM

示例一：页面开发

WXML<!-- pages/user/user.wxml -->
<view class="container">
  <view class="profile" bindtap="onAvatarTap">
    <image src="{{userInfo.avatar}}" mode="aspectFill" />
    <text>{{userInfo.name}}</text>
  </view>
  <view wx:for="{{menus}}" wx:key="id" class="menu-item" bindtap="onMenuTap" data-id="{{item.id}}">
    <text>{{item.title}}</text>
  </view>
</view>
JavaScript// pages/user/user.js
Page({
  data: {
    userInfo: { avatar: '', name: '未登录' },
    menus: [
      { id: 'orders', title: '我的订单' },
      { id: 'settings', title: '设置' },
    ],
  },

  onLoad(options) {
    this.loadUserInfo();
  },

  async loadUserInfo() {
    const res = await wx.request({ url: '/api/user' });
    this.setData({ userInfo: res.data });
  },

  onAvatarTap() {
    wx.navigateTo({ url: '/pages/login/login' });
  },

  onMenuTap(e) {
    const id = e.currentTarget.dataset.id;
    wx.navigateTo({ url: `/pages/${id}/${id}` });
  },
});

示例二：自定义组件

JSON// components/rating/rating.json
{ "component": true }
JavaScript// components/rating/rating.js
Component({
  properties: {
    value: { type: Number, value: 0 },
    max: { type: Number, value: 5 },
    size: { type: Number, value: 24 },
    readonly: { type: Boolean, value: false },
  },

  data: {
    stars: [],
  },

  observers: {
    'value, max': function(value, max) {
      const stars = [];
      for (let i = 1; i <= max; i++) {
        stars.push(i <= value ? 'full' : i - 0.5 <= value ? 'half' : 'empty');
      }
      this.setData({ stars });
    },
  },

  methods: {
    onStarTap(e) {
      if (this.data.readonly) return;
      const index = e.currentTarget.dataset.index + 1;
      this.triggerEvent('change', { value: index });
    },
  },
});

示例四：网络请求封装

JavaScript// utils/request.js
const BASE_URL = 'https://api.example.com';

function request(options) {
  return new Promise((resolve, reject) => {
    wx.request({
      url: BASE_URL + options.url,
      method: options.method || 'GET',
      data: options.data,
      header: {
        'Content-Type': 'application/json',
        'Authorization': `Bearer ${wx.getStorageSync('token')}`,
        ...options.header,
      },
      success(res) {
        if (res.statusCode === 200) {
          resolve(res.data);
        } else if (res.statusCode === 401) {
          wx.navigateTo({ url: '/pages/login/login' });
          reject(new Error('未登录'));
        } else {
          reject(new Error(`HTTP ${res.statusCode}`));
        }
      },
      fail: reject,
    });
  });
}

// 使用
const data = await request({
  url: '/api/products',
  method: 'GET',
  data: { page: 1 },
});

示例五：性能优化要点

text1. setData 优化
   - 不要频繁调用 setData（合并更新）
   - 只传必要的数据（不要传整个大对象）
   - 避免 setData 设置不在 WXML 中使用的数据

2. 列表渲染优化
   - 必须加 wx:key
   - 长列表使用 recycle-view（虚拟列表）
   - 避免在 wx:for 中使用复杂计算

3. 图片优化
   - 使用 mode 属性（aspectFill/widthFix）
   - 使用 lazy-load 懒加载
   - CDN 压缩 + WebP 格式

4. 分包优化
   - 主包只放 TabBar 页面和公共资源
   - 独立分包实现页面独立运行
   - 分包预加载提升体验

5. 避免使用 CSS :hover（移动端无效）
   使用 hover-class 替代

4. 常见问题与坑点

setData 为什么不能频繁调用？ +

setData 是跨线程通信，每次调用都会：① 逻辑层序列化数据；② 经 Native 层转发；③ 渲染层反序列化并重新渲染。频繁调用导致通信开销大。最佳实践：合并多次 setData 为一次；只传变化的数据字段。

小程序怎么调试真机？ +

微信开发者工具 → 预览/真机调试 → 扫码在手机上打开。真机调试支持 vConsole 和远程调试。注意：部分 API（支付、扫码）只能在真机测试，开发者工具中模拟。

🚫 小程序不支持 DOM 操作

小程序没有 document/window 对象，不能使用 jQuery 等 DOM 库。所有 UI 更新必须通过 setData 驱动。如果需要动态效果，使用 WXS（WeiXin Script）响应事件或 Canvas 绑定动画。

1小程序的双线程模型是什么？
渲染层（WebView）处理 WXML/WXSS 渲染，逻辑层（JSCore）执行 JS。两者通过 Native 层通信。优势：JS 不阻塞 UI 渲染，更安全（不能直接操作 DOM）。代价：通信有开销，setData 是跨线程通信。
2小程序的 setData 有什么性能问题？怎么优化？
setData 是跨线程通信，开销大。优化：① 合并多次 setData 为一次；② 只传变化字段（不要每次传整个对象）；③ 避免设置不在 WXML 中使用的数据（用 this._privateData 代替）；④ 长列表用虚拟列表。
