事件循环机制

事件循环是 JavaScript 实现异步的核心机制——理解宏任务、微任务的执行顺序，才能精准预测代码行为，这是面试必考、实战必用的知识点。

1. 核心概念与定义

事件循环（Event Loop）是浏览器（或 Node.js）提供的一种机制，让单线程的 JavaScript 能够执行异步非阻塞操作。它通过不断循环检查调用栈和任务队列，决定下一个要执行的任务。

JavaScript 是单线程语言，同一时间只能执行一段代码。事件循环的工作方式是：执行同步代码 → 清空微任务队列 → 取一个宏任务执行 → 再清空微任务 → 如此循环。这就是为什么异步回调不会阻塞主线程。

理解事件循环的关键在于分清宏任务（Macrotask）和微任务（Microtask）的优先级：每个宏任务执行完后，必须清空所有微任务，才会执行下一个宏任务。

2. 关键特性与工作原理

2.1 事件循环模型

text┌───────────────────────────┐
│       调用栈 (Call Stack)   │  ← 同步代码在此执行
└──────────────┬────────────┘
               │ 栈空

┌───────────────────────────┐
│    微任务队列 (Microtask)   │  ← Promise.then, MutationObserver

└──────────────┬────────────┘
               │ 队列空
               ▼
┌───────────────────────────┐
│    宏任务队列 (Macrotask)   │  ← setTimeout, setInterval, I/O
│  [task1, task2, ...]      │  ← 每次只取一个
└──────────────┬────────────┘
               │ 执行完一个宏任务
               ▼
          回到清空微任务队列

2.3 执行顺序规则

💡 核心规则（牢记）

1. 同步代码先执行（在调用栈中）
2. 同步代码执行完 → 清空所有微任务
3. 取一个宏任务执行
4. 该宏任务执行完 → 再次清空所有微任务
5. 可能触发 UI 渲染（在宏任务之间）
6. 重复步骤 3-5

2.4 requestAnimationFrame 的位置

在浏览器中，rAF 在微任务之后、浏览器渲染之前执行。它不属于宏任务也不属于微任务，而是渲染流程的一部分。这使得它适合做动画——保证在下一帧绘制前更新样式。

text宏任务 → 微任务（清空）→ requestAnimationFrame → 渲染 → 下一个宏任务

JavaScriptconsole.log('1');

示例三：利用微任务确保 DOM 更新

JavaScript// ❌ 直接读取可能获取旧值
element.style.height = '100px';
console.log(element.offsetHeight); // 可能还是旧值

// ✅ 方案1：用微任务确保在渲染前获取最新布局
element.style.height = '100px';
Promise.resolve().then(() => {
  // 微任务在渲染前执行，但此时布局已计算
  console.log(element.offsetHeight); // 100
});

// ✅ 方案2：用 requestAnimationFrame 确保在渲染前更新
element.style.height = '100px';
requestAnimationFrame(() => {
  // 在下一帧绘制前执行
  console.log(element.offsetHeight);
});

// ✅ 方案3：双 rAF 确保渲染已完成
element.style.height = '100px';
requestAnimationFrame(() => {
  requestAnimationFrame(() => {
    // 此时上一帧已渲染完毕
    console.log(element.offsetHeight); // 100
  });
});

示例四：实现可中断的异步任务

JavaScript/**
 * 使用事件循环实现可中断的任务处理
 * 每处理一批数据后让出主线程，保持 UI 响应
 */
async function processLargeArray(array, handler, batchSize = 100) {
  let index = 0;
  
  return new Promise((resolve) => {
    function processBatch() {
      const end = Math.min(index + batchSize, array.length);
      
      while (index < end) {
        handler(array[index], index);
        index++;
      }
      
      if (index < array.length) {
        // 让出主线程：使用 setTimeout(0) 让 UI 有机会响应
        setTimeout(processBatch, 0);
      } else {
        resolve();
      }
    }
    
    processBatch();
  });
}

// 使用
const data = Array.from({ length: 10000 }, (_, i) => i);
await processLargeArray(data, (item, idx) => {
  // 处理每一项
  if (idx % 1000 === 0) console.log(`已处理 ${idx} 项`);
});

示例五：queueMicrotask 与调度

JavaScript// queueMicrotask: 显式添加微任务（比 Promise.resolve().then() 更语义化）
function defer(fn) {
  queueMicrotask(fn);
}

// 用途：确保回调在当前调用栈清空后、下一个宏任务前执行
function emitEvent(event) {
  // 同步收集监听器，异步触发（避免在监听器中修改当前执行流）
  const listeners = this.listeners.slice();
  queueMicrotask(() => {
    for (const listener of listeners) {
      try {
        listener(event);
      } catch (err) {
        console.error('Event listener error:', err);
      }
    }
  });
}

// 调度优先级示例
console.log('sync');
queueMicrotask(() => console.log('microtask'));
setTimeout(() => console.log('macrotask'), 0);
// 输出：sync → microtask → macrotask

4. 常见问题与坑点

setTimeout(fn, 0) 真的是 0ms 后执行吗？ +

不是。HTML 规范规定 setTimeout 最小延迟为 4ms（嵌套超过 5 层后）。且即使延迟到期，回调也必须等当前宏任务和所有微任务执行完才会执行。此外，浏览器标签页在后台时，定时器可能被限流至 1s 甚至更长。

Promise.then 是微任务，new Promise 的 executor 呢？ +

new Promise 的 executor（传入的函数）是同步执行的。只有 .then/.catch/.finally 的回调才是微任务。new Promise(resolve => { console.log(1); resolve(); }).then(() => console.log(2)); 输出 1, 2。

Node.js 和浏览器的事件循环有什么区别？ +

Node.js 的事件循环分 6 个阶段（timers → pending → idle → prepare → poll → check → close）。微任务优先级：process.nextTick > Promise.then。浏览器只有宏任务和微任务两个队列。Node 11+ 的行为已向浏览器对齐。

🚫 微任务中无限添加微任务会阻塞渲染

微任务队列是在同步代码后、渲染前清空的。如果在微任务中不断添加新微任务（如递归 Promise.resolve().then()），队列永远清不完，渲染被阻塞，页面卡死。这不是无限循环，但效果等同。

⚠ async 函数中的 await 不是暂停整个程序

await 只暂停当前 async 函数的执行，将后面的代码注册为微任务。主线程继续执行其他代码。多个 async 函数可以并行运行，不会互相阻塞。

1宏任务和微任务有什么区别？执行顺序是什么？
宏任务：setTimeout、I/O、UI 事件等，每次只取一个。微任务：Promise.then、MutationObserver 等，每次清空整个队列。执行顺序：同步代码 → 清空微任务 → 取一个宏任务 → 清空微任务 → 循环。微任务优先级高于宏任务。
2为什么 await 后面的代码是微任务？
async/await 是 Promise + generator 的语法糖。await 后面的代码等价于 .then() 回调，自然也是微任务。async function f() { await p; code; } 等价于 function f() { return p.then(() => code); }。
3如何确保 DOM 更新后再执行操作？
① Promise.resolve().then() — 微任务，在渲染前执行，可获取最新布局计算值；② requestAnimationFrame — 下一次渲染前执行，适合动画；③ 双 rAF — 确保渲染已完成。Vue 的 nextTick 原理类似，使用微任务（Promise.then）确保 DOM 更新后执行。
