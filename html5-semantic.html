HTML5 语义化

语义化是现代 HTML 开发的基石——用正确的标签表达正确的内容，让代码既面向浏览器，也面向人与机器。

1. 核心概念与定义

HTML 语义化是指根据内容的结构和含义，选择最恰当的 HTML 标签来构建页面，而不是一味地使用 <div> 和 <span> 这种无语义的容器标签。简单来说，标题用 <h1>~<h6>，段落用 <p>，导航用 <nav>，文章用 <article>——让标签名本身就"说明"其内容是什么。

在 HTML5 之前，网页结构几乎全部由 <div> 堆砌而成，通常通过 id 或 class 来区分各部分（如 <div id="header">、<div class="nav">）。HTML5 引入了一系列语义化标签（<header>、<nav>、<main>、<article>、<section>、<aside>、<footer>），让开发者可以用标准化的方式描述页面结构，这些标签不仅在视觉上没有特殊效果，更重要的是为机器（搜索引擎、屏幕阅读器、爬虫）提供了明确的内容语义信息。

语义化的重要性体现在三个方面：可访问性（Accessibility）——屏幕阅读器等辅助技术依赖语义标签来理解页面结构，为视障用户提供导航和内容解读；SEO（搜索引擎优化）——搜索引擎爬虫通过语义标签更准确地理解页面内容权重和层级，从而提高搜索排名；可维护性——语义化的代码自文档化，团队成员可以快速理解页面结构，降低沟通和协作成本。

2. 关键特性与工作原理

2.1 HTML5 核心语义标签

标签语义使用场景
<header>页眉或区块头部网站顶部导航区、article 的标题区
<nav>导航链接区域主导航、面包屑、侧边栏导航
<main>页面主体内容每页唯一的核心内容区
<article>独立的完整内容博客文章、新闻条目、用户评论
<section>内容的主题性分组章节、标签页内容、专题区块
<aside>辅助性旁侧内容侧边栏、相关链接、广告、引用
<footer>页脚或区块底部版权信息、联系方式、相关链接
<figure>自包含的引用内容图片、图表、代码块配说明
<figcaption>figure 的标题图片/图表的说明文字
<time>日期/时间发布日期、事件时间
<address>联系信息作者邮箱、地址、电话
<mark>标记/高亮文本搜索结果高亮、引用强调

2.2 article vs section 的区别

这是语义化中最常见的困惑点。<article> 代表一段独立的、可被单独引用或分发的内容——比如一篇博客文章、一条新闻、一个用户评论。判断标准：这段内容能否被单独拿出来（如 RSS 订阅）仍然有意义？如果能，就是 article。

<section> 代表文档中的一个主题性分组，通常带有标题。它不一定独立完整，但它是某个更大内容的一个逻辑部分。比如文章中的"概述"、"方法"、"结论"各节，或首页的"推荐商品"、"最新动态"区块。

💡 判断技巧

问自己一个问题：这段内容能否独立存在（如在 RSS 中单独显示）？能 → article；不能但它是某个主题分组 → section；都不是 → div。article 内部可以包含多个 section，section 内部也可以包含 article。

2.3 文档大纲算法

HTML5 引入了文档大纲（Document Outline）的概念，通过标题层级（h1-h6）和 section/article 等语义标签自动生成页面的结构大纲。理论上，每个 section/article 可以有自己的 h1，不影响全局大纲层级。但实际上，大多数浏览器和辅助技术并未完全实现这一算法，因此最佳实践仍然是在整个页面中保持 h1-h6 的层级递进，每页只有一个 h1。

2.4 ARIA 角色

WAI-ARIA（Web Accessibility Initiative - Accessible Rich Internet Applications）是一套为 Web 内容增加语义的属性规范，主要用于弥补 HTML 语义不足的场景。HTML5 语义标签自带隐式 ARIA 角色：

HTML5 标签隐式 ARIA 角色
<header>role="banner"（顶级时）
<nav>role="navigation"
<main>role="main"
<article>role="article"
<aside>role="complementary"
<footer>role="contentinfo"（顶级时）
<section>role="region"（有标题时）
⚠ 第一规则：不要重复声明 ARIA 角色

ARIA 的第一规则是：如果你能使用原生 HTML 元素或属性来达到目的，就不要使用 ARIA。例如，<nav role="navigation"> 是多余的——nav 已经隐式拥有 navigation 角色。重复声明不会出错，但增加了代码噪音。

2.5 语义化与 SEO

搜索引擎爬虫通过解析 HTML 标签来理解页面内容。语义化标签帮助爬虫：①识别页面的核心内容区（main）；②区分导航、正文和辅助信息；③理解内容的层级关系（h1-h6）；④识别独立内容单元（article）。合理的语义结构可以提升页面在搜索结果中的表现，尤其是结构化数据（Schema.org）配合语义标签使用时，可以生成富文本搜索结果。

<head>
  <meta charset="UTF-8">

4. 常见问题与坑点

header 和 footer 能在页面中出现多次吗？ +

可以。header 和 footer 不限于页面级别，每个 article 或 section 都可以有自己的 header 和 footer。例如一篇文章的头部（标题+作者+日期）是一个 header，文章尾部的版权声明是一个 footer。但需要注意：当 header 作为页面顶级元素时，它的隐式 ARIA 角色是 banner；当它嵌套在 article/section 内时，没有 banner 角色。同理，顶级 footer 的角色是 contentinfo，嵌套的则不是。

section 和 div 该用哪个？ +

关键判断标准：这段内容是否有一个明确的主题，且通常应该有标题？如果是 → section；如果只是为了样式或脚本方便而包裹元素，没有语义含义 → div。section 不应该被用作通用容器。常见错误：用 section 替代 div 来做纯布局容器，既没有标题也没有主题含义，这比用 div 更糟糕——因为 section 给出了"这里有主题内容"的错误暗示。

main 标签有什么限制？ +

main 标签的限制：① 每个页面只能有一个 main；② main 不能嵌套在 article、aside、header、footer、nav 内部；③ main 应该包含页面的核心内容，不包括全局导航、logo、搜索框等辅助元素。main 的隐式 ARIA 角色是 main，屏幕阅读器提供了直接跳转到 main 的快捷键，这是视障用户最常用的导航方式之一。

🚫 常见错误：用 h1 做样式而非层级

有些开发者为了获得大字体而使用 h1，或者在同一个页面使用多个 h1。正确做法：每页只有一个 h1（作为页面主标题），然后按层级使用 h2、h3 等。需要不同视觉大小时，用 CSS 修改样式，而不是更改标签层级。

⚠ 注意：nav 不要滥用

nav 应该用于主要的导航块，不是所有链接集合都需要 nav。页脚的一组链接通常不需要 nav 标签，除非它确实是重要的导航（如网站地图链接）。一个页面可以有多个 nav，但每个都应用 aria-label 区分。

💡 使用 aria-labelledby 关联标题

给 section 加上 aria-labelledby 指向其内部的标题 id，这样屏幕阅读器可以告知用户当前区域的主题。如：<section aria-labelledby="intro-heading"> + <h2 id="intro-heading">简介</h2>。

面试题

1什么是 HTML 语义化？为什么要语义化？
语义化是用正确的标签表达正确的内容含义。好处：① 可访问性——屏幕阅读器通过语义标签为视障用户导航；② SEO——搜索引擎通过语义标签理解内容权重；③ 可维护性——代码自文档化，团队协作更高效；④ 标准化——统一的语义结构便于工具和浏览器处理。
2article 和 section 有什么区别？
article 代表独立的、可被单独分发的内容（如博客文章、新闻条目），它脱离上下文仍然有意义。section 代表文档中的主题性分组，通常带标题，但不一定独立完整。判断：能单独存在 → article；是主题分组 → section；纯布局容器 → div。两者可以互相嵌套。
3HTML5 语义标签有哪些隐式 ARIA 角色？为什么不要重复声明？
header→banner（顶级时）、nav→navigation、main→main、article→article、aside→complementary、footer→contentinfo（顶级时）。不要重复声明因为：ARIA 第一规则是能用原生 HTML 就不要用 ARIA，重复声明是冗余代码，且如果未来标签的隐式角色变化，可能导致冲突。
