包管理器 npm/yarn

包管理器是前端工程化的基础设施——理解依赖管理、语义版本、锁文件和包发布，是从"写代码"到"做项目"的关键一步。

1. 核心概念与定义

npm（Node Package Manager）是 Node.js 的默认包管理器，拥有世界上最大的开源注册表。yarn是 Facebook 推出的替代方案，解决了早期 npm 的性能和安全问题。现代 npm 已大幅改进，两者差距缩小。

pnpm是新一代包管理器，通过硬链接和符号链接共享依赖，节省磁盘空间，安装速度更快，且严格隔离依赖。

包管理器的核心职责：下载/安装依赖、管理依赖版本、解析依赖树、执行脚本、发布包。

2.4 幽灵依赖问题

npm/yarn 的扁平 node_modules 结构会导致幽灵依赖：项目可以 import 未在 package.json 中声明的包（因为它们被其他依赖提升到了顶层）。pnpm 通过严格的依赖隔离解决了此问题。

text">node_modules/
├── express/        ← package.json 声明的依赖
├── body-parser/    ← express 的依赖（被提升）
├── qs/             ← body-parser 的依赖（被提升）← 幽灵依赖！
└── ...

4. 常见问题与坑点

package-lock.json 要提交到 Git 吗？ +

必须提交！锁文件确保所有环境安装相同版本的依赖，避免"我本地能跑"的问题。唯一例外：库项目（library）可能不需要锁文件，因为使用者应该获取最新兼容版本。

npm install 和 npm ci 的区别？ +

npm install：根据 package.json 解析依赖，可能更新 lockfile，安装速度较慢。npm ci：严格按 lockfile 安装，不修改 lockfile，安装前删除 node_modules，速度更快且可复现。CI/CD 环境推荐用 npm ci。

依赖安装失败怎么排查？ +

步骤：① 删除 node_modules 和 lockfile 重新安装；② 检查 Node.js 版本是否符合 engines 要求；③ 检查网络/代理配置（.npmrc）；④ 检查是否有 Python/build-tools 依赖（node-gyp）；⑤ 用 --verbose 查看详细日志；⑥ 检查注册表是否可用。

🚫 不要滥用 --force

npm install --force 会绕过所有安全检查，可能导致安装不兼容的版本。应该先理解报错原因，针对性解决，而非暴力强制。

⚠ 全局安装 vs 项目本地安装

构建工具（webpack、vite、eslint）应安装为 devDependencies，通过 npx 或 npm scripts 运行。全局安装仅用于跨项目的 CLI 工具（如 pm2、serve）。全局安装的版本可能与项目不兼容。

1npm、yarn、pnpm 有什么区别？
npm：Node.js 默认，扁平 node_modules，有幽灵依赖。yarn：并行安装、离线缓存、确定性安装。pnpm：硬链接共享存储（节省磁盘）、严格依赖隔离（无幽灵依赖）、安装最快。新项目推荐 pnpm。
2什么是幽灵依赖？怎么解决？
扁平 node_modules 让未声明的包可被 import。解决方案：① 使用 pnpm（严格隔离依赖）；② 使用 eslint-plugin-import 检测未声明依赖；③ 开启 npm 的 --install-strategy=nested。pnpm 是最彻底的方案。
3dependencies 和 devDependencies 的区别？什么时候用哪个？
dependencies：运行时需要的包（vue, axios）。devDependencies：仅开发时需要的包（webpack, eslint, jest）。库项目要注意：npm install 时 devDependencies 不安装，所以构建工具应放 devDependencies，运行时依赖放 dependencies。
