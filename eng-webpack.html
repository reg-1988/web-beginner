Webpack 基础

Webpack 是最成熟的前端模块打包器——理解核心概念、Loader、Plugin 和优化配置，是掌握前端工程化的关键。

1. 核心概念与定义

Webpack是一个静态模块打包工具。它将项目中的各种资源（JS、CSS、图片、字体等）视为模块，通过依赖关系图（Dependency Graph）分析模块间的引用，最终打包成浏览器可用的静态文件。

Webpack 的核心理念：一切皆模块，按需加载。它通过 Loader 处理非 JS 资源，通过 Plugin 扩展构建流程。

虽然 Vite 等新工具在开发体验上更优，但 Webpack 仍是企业级项目的主流选择，理解其原理有助于理解所有打包工具的设计思想。

2. 关键特性与工作原理

2.1 五大核心概念

概念作用配置字段
Entry（入口）构建依赖图的起点entry
Output（输出）打包产物的输出位置和命名output
Loader（加载器）处理非 JS 文件，转换为 JS 模块module.rules
Plugin（插件）扩展构建能力（压缩、拷贝、环境变量等）plugins
Mode（模式）development / production，内置优化mode

2.2 构建流程

text初始化参数 → 开始编译 → 编译模块 → 完成编译 → 输出资源 → 输出完成
   ↓            ↓           ↓           ↓          ↓
读取配置     从 Entry    调用 Loader  生成 chunk  写入文件
合并参数     递归解析     转换源码     组装模块    输出目录
             依赖图      + Plugin     依赖关系

示例二：生产环境优化配置

JavaScriptconst MiniCssExtractPlugin = require('mini-css-extract-plugin');
const CssMinimizerPlugin = require('css-minimizer-webpack-plugin');
const TerserPlugin = require('terser-webpack-plugin');

module.exports = {
  mode: 'production',
  output: {
    filename: 'js/[name].[contenthash:8].js',
    chunkFilename: 'js/[name].[contenthash:8].chunk.js',
    assetModuleFilename: 'assets/[hash:8][ext][query]',
  },
  module: {
    rules: [
      {
        test: /\.css$/,
        use: [MiniCssExtractPlugin.loader, 'css-loader', 'postcss-loader'],
      },
    ],
  },
  plugins: [
    new MiniCssExtractPlugin({
      filename: 'css/[name].[contenthash:8].css',
    }),
  ],
  optimization: {
    minimize: true,
    minimizer: [new TerserPlugin(), new CssMinimizerPlugin()],
    splitChunks: {
      chunks: 'all',
      cacheGroups: {
        // 第三方库单独打包
        vendor: {
          test: /[\\/]node_modules[\\/]/,
          name: 'vendor',
          chunks: 'all',
          priority: 10,
        },
        // 公共代码提取
        common: {
          minChunks: 2,
          name: 'common',
          chunks: 'all',
          priority: 5,
          reuseExistingChunk: true,
        },
      },
    },
    // 运行时代码单独提取
    runtimeChunk: 'single',
  },
  // 生产环境不生成 source map
  devtool: 'hidden-source-map',
};

示例四：自定义 Plugin

JavaScript/**
 * 自定义 Plugin：构建完成后生成文件清单
 */
class FileListPlugin {
  constructor(options = {}) {
    this.filename = options.filename || 'filelist.md';
  }

  apply(compiler) {
    // 在 emit 阶段（输出文件到目录之前）插入钩子
    compiler.hooks.emit.tapAsync('FileListPlugin', (compilation, callback) => {
      // 获取所有输出文件名
      const fileNames = Object.keys(compilation.assets);
      
      // 生成清单内容
      let content = '# 构建产物清单\n\n';
      content += `构建时间: ${new Date().toISOString()}\n\n`;
      content += '| 文件 | 大小 |\n| --- | --- |\n';
      
      for (const name of fileNames) {
        const size = compilation.assets[name].size();
        content += `| ${name} | ${(size / 1024).toFixed(2)} KB |\n`;
      }
      
      // 添加到输出文件
      compilation.assets[this.filename] = {
        source: () => content,
        size: () => content.length,
      };
      
      callback();
    });
  }
}

// 使用
// plugins: [new FileListPlugin({ filename: 'manifest.md' })]

4. 常见问题与坑点

Webpack 和 Vite 有什么区别？ +

Webpack：先打包再启动，开发速度随项目增大变慢，配置复杂但功能强大。Vite：开发时基于 ESM 不打包，启动极快；生产用 Rollup 打包。新项目推荐 Vite，大型存量项目 Webpack 仍是主流。

Loader 和 Plugin 的区别？ +

Loader 是文件转换器，将非 JS 资源转为 JS 模块（如 css-loader 解析 CSS），在模块构建阶段执行。Plugin 是构建流程扩展器，监听 Webpack 生命周期钩子执行自定义逻辑（如生成 HTML、压缩代码），贯穿整个构建流程。

contenthash 变化导致缓存失效怎么办？ +

使用 runtimeChunk 将 Webpack 运行时代码单独提取，避免业务代码改变导致 runtime 变化。同时使用 splitChunks 将第三方库单独打包，业务代码变化不影响 vendor hash。确保 moduleIds 使用 deterministic 算法。

🚫 不要在生产环境使用 style-loader

style-loader 将 CSS 注入 JS 并通过 style 标签插入 DOM，导致 JS 体积膨胀和 FOUC（无样式闪烁）。生产环境务必使用 MiniCssExtractPlugin 将 CSS 提取为独立文件。

⚠ Loader 执行顺序是从右到左

use: ['style-loader', 'css-loader', 'postcss-loader'] 实际执行顺序：postcss → css → style。可理解为管道：源文件经过 postcss 处理，再给 css-loader 解析，最后 style-loader 注入 DOM。

1Webpack 的构建流程是什么？
初始化：读取配置、创建 Compiler。编译：从 Entry 出发，调用 Loader 转换模块，递归解析依赖关系，构建依赖图。输出：根据依赖图组装 Chunk，写入文件系统。整个过程中 Plugin 通过钩子参与各阶段。
2Webpack 的热更新（HMR）原理？
Webpack-dev-server 与浏览器建立 WebSocket 连接。文件修改后 Webpack 重新编译，生成补丁文件（manifest + update chunk），通过 WebSocket 通知浏览器。浏览器下载补丁，通过 HMR Runtime 替换对应模块。模块需要自行定义 accept 回调处理更新。
3如何优化 Webpack 构建速度？
① 持久化缓存（cache: filesystem）；② 缩小 Loader 范围（exclude node_modules）；③ 使用 thread-loader 多线程编译；④ DLL 预编译第三方库；⑤ 合理使用 source-map 类型；⑥ resolve.alias 减少搜索路径；⑦ 使用 esbuild-loader 替代 babel-loader。
