PWA 基础

PWA 让 Web 应用拥有原生 App 的能力——离线可用、推送通知、安装到桌面，是移动端 H5 进化的方向。

1. 核心概念与定义

PWA（Progressive Web App）不是一种技术，而是一组 Web 技术的集合，目标是让 Web 应用具备原生 App 的体验：可安装、离线可用、推送通知、全屏运行。PWA 是渐进增强的——即使浏览器不支持某些特性，应用仍能正常工作。

PWA 的三大核心能力：Service Worker（离线缓存 + 网络代理）、Web App Manifest（安装到桌面）、Push API（推送通知）。

2. 关键特性与工作原理

2.1 PWA 核心技术

技术作用浏览器支持
Service Worker离线缓存、网络拦截、后台同步主流全支持
Web App Manifest定义应用名称、图标、启动方式主流全支持
Cache API编程式缓存管理主流全支持
Push API服务器推送通知Chrome/Firefox/Edge
Background Sync后台数据同步Chrome/Edge

2.2 Service Worker 生命周期

text">注册 → 安装(install) → 等待(waiting) → 激活(activate) → 运行(fetch/push/sync)

install：预缓存关键资源
waiting：等待旧 SW 控制的页面全部关闭
activate：清理旧缓存，接管页面
fetch：拦截网络请求，决定从缓存还是网络获取

2.3 缓存策略

策略流程适用场景
Cache First缓存优先，失败走网络静态资源（JS/CSS/图片）
Network First网络优先，失败走缓存API 数据、HTML 页面
Stale While Revalidate先返回缓存，同时更新非关键数据、配置
Cache Only仅缓存离线页面
Network Only仅网络非 GET 请求

3. 代码示例与最佳实践

示例一：Service Worker 注册与基础缓存

JavaScript// main.js — 注册 Service Worker
if ('serviceWorker' in navigator) {
  window.addEventListener('load', async () => {
    try {
      const reg = await navigator.serviceWorker.register('/sw.js');
      console.log('SW 注册成功:', reg.scope);
    } catch (err) {
      console.error('SW 注册失败:', err);
    }
  });
}

// sw.js — Service Worker
const CACHE_NAME = 'app-v1';
const PRECACHE_URLS = [
  '/',
  '/index.html',
  '/css/style.css',
  '/js/main.js',
  '/offline.html',
];

// 安装：预缓存关键资源
self.addEventListener('install', (event) => {
  event.waitUntil(
    caches.open(CACHE_NAME)
      .then(cache => cache.addAll(PRECACHE_URLS))
      .then(() => self.skipWaiting()) // 跳过等待，立即激活
  );
});

// 激活：清理旧缓存
self.addEventListener('activate', (event) => {
  event.waitUntil(
    caches.keys().then(keys =>
      Promise.all(
        keys.filter(key => key !== CACHE_NAME)
            .map(key => caches.delete(key))
      )
    ).then(() => self.clients.claim()) // 立即接管页面
  );
});

// 拦截请求：Cache First 策略
self.addEventListener('fetch', (event) => {
  event.respondWith(
    caches.match(event.request)
      .then(cached => cached || fetch(event.request))
  );
});

示例二：Network First 策略（API 数据）

JavaScript// sw.js — Network First 策略
self.addEventListener('fetch', (event) => {
  const { request } = event;

  // API 请求使用 Network First
  if (request.url.includes('/api/')) {
    event.respondWith(
      fetch(request)
        .then(response => {
          // 成功后缓存响应副本
          const clone = response.clone();
          caches.open('api-cache').then(cache => cache.put(request, clone));
          return response;
        })
        .catch(() => {
          // 网络失败，从缓存读取
          return caches.match(request).then(cached => {
            return cached || caches.match('/offline.html');
          });
        })
    );
    return;
  }

  // 静态资源使用 Cache First
  event.respondWith(
    caches.match(request).then(cached => cached || fetch(request))
  );
});

示例四：推送通知

JavaScript// 请求通知权限
async function requestNotificationPermission() {
  const permission = await Notification.requestPermission();
  if (permission === 'granted') {
    console.log('通知权限已获取');
    // 订阅推送
    const registration = await navigator.serviceWorker.ready;
    const subscription = await registration.pushManager.subscribe({
      userVisibleOnly: true,
      applicationServerKey: 'YOUR_VAPID_PUBLIC_KEY',
    });
    // 将 subscription 发送到服务器
    await fetch('/api/push/subscribe', {
      method: 'POST',
      body: JSON.stringify(subscription),
    });
  }
}

// sw.js — 处理推送事件
self.addEventListener('push', (event) => {
  const data = event.data?.json() ?? { title: '新消息', body: '你有一条新消息' };
  event.waitUntil(
    self.registration.showNotification(data.title, {
      body: data.body,
      icon: '/icons/icon-192.png',
      badge: '/icons/badge-72.png',
      vibrate: [100, 50, 100],
      data: { url: data.url || '/' },
    })
  );
});

// 点击通知
self.addEventListener('notificationclick', (event) => {
  event.notification.close();
  event.waitUntil(
    clients.openWindow(event.notification.data.url)
  );
});

示例五：Workbox 简化配置

JavaScript// workbox-config.js（推荐使用 Workbox 简化 SW 开发）
import { precacheAndRoute } from 'workbox-precaching';
import { registerRoute } from 'workbox-routing';
import { StaleWhileRevalidate, CacheFirst, NetworkFirst } from 'workbox-strategies';
import { ExpirationPlugin } from 'workbox-expiration';

// 预缓存（由 Workbox 构建时自动注入清单）
precacheAndRoute(self.__WB_MANIFEST);

// API：Stale While Revalidate
registerRoute(
  ({ url }) => url.pathname.startsWith('/api/'),
  new StaleWhileRevalidate({ cacheName: 'api-cache' })
);

// 图片：Cache First + 30天过期
registerRoute(
  ({ request }) => request.destination === 'image',
  new CacheFirst({
    cacheName: 'image-cache',
    plugins: [new ExpirationPlugin({ maxEntries: 100, maxAgeSeconds: 30 * 24 * 3600 })],
  })
);

// HTML：Network First
registerRoute(
  ({ request }) => request.mode === 'navigate',
  new NetworkFirst({
    cacheName: 'html-cache',
    plugins: [new ExpirationPlugin({ maxEntries: 50 })],
  })
);

4. 常见问题与坑点

Service Worker 更新后用户还是看到旧版本？ +

新 SW 安装后进入 waiting 状态，直到所有旧标签页关闭。解决方案：① skipWaiting() 跳过等待（install 事件中调用）；② clients.claim() 立即接管（activate 事件中调用）；③ 提示用户刷新页面。注意：skipWaiting 可能导致新旧代码不一致。

PWA 在 iOS 上的限制？ +

iOS Safari 对 PWA 支持有限：① 推送通知仅 iOS 16.4+ 支持；② 缓存限制 50MB；③ 不支持 Background Sync；④ 添加到主屏后独立存储，与 Safari 数据不共享；⑤ 状态栏颜色等部分 manifest 字段不支持。

🚫 SW 缓存策略选择错误

HTML 页面不要用 Cache First（用户永远看到旧页面），API 数据不要用 Cache Only（数据永远不更新）。通用原则：频繁变化的内容用 Network First，稳定的静态资源用 Cache First。

1Service Worker 的工作原理？
SW 是独立于页面的 Worker 线程，生命周期：install（预缓存）→ waiting（等待旧SW）→ activate（清理旧缓存、接管页面）→ fetch（拦截请求）。SW 可以拦截所有同源请求，决定从缓存还是网络获取。SW 在页面关闭后仍可运行（处理推送、同步等）。
2PWA 有哪些缓存策略？
Cache First（缓存优先）、Network First（网络优先）、Stale While Revalidate（先缓存后更新）、Cache Only、Network Only。选择原则：静态资源用 Cache First，动态数据用 Network First，可容忍短暂的旧数据用 Stale While Revalidate。
