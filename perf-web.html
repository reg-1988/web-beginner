Web 性能优化

性能是用户体验的基石——掌握核心指标、加载优化、运行时优化和工具链，才能系统性地提升 Web 应用性能。

1. 核心概念与定义

Web 性能优化是让网页加载更快、交互更流畅的系统性工程。Google 的 Core Web Vitals（核心网页指标）定义了三个关键指标：LCP（加载性能）、FID/INP（交互性能）、CLS（视觉稳定性）。

性能优化不是单一的技巧，而是贯穿网络传输→资源加载→页面渲染→用户交互全链路的系统性工作。每个环节都有对应的优化手段。

示例二：防抖与节流

JavaScript/**
 * 防抖：停止触发 n 毫秒后执行
 */
function debounce(fn, delay = 300) {
  let timer = null;
  return function(...args) {
    clearTimeout(timer);
    timer = setTimeout(() => fn.apply(this, args), delay);
  };
}

/**
 * 节流：每 n 毫秒最多执行一次
 */
function throttle(fn, interval = 300) {
  let lastTime = 0;
  return function(...args) {
    const now = Date.now();
    if (now - lastTime >= interval) {
      lastTime = now;
      fn.apply(this, args);
    }
  };
}

// 使用场景
// 防抖：搜索输入、窗口 resize 结束后重新计算
// 节流：滚动事件、拖拽移动、鼠标移动

// 搜索框
input.addEventListener('input', debounce((e) => {
  search(e.target.value);
}, 500));

// 滚动加载
window.addEventListener('scroll', throttle(() => {
  if (isNearBottom()) loadMore();
}, 200));

示例四：避免 CLS 的技巧

CSS/* 1. 图片/视频预留空间 */
.img-container {
  /* 使用 aspect-ratio 预留空间 */
  aspect-ratio: 16 / 9;
  width: 100%;
}
.img-container img {
  width: 100%;
  height: 100%;
  object-fit: cover;
}

/* 2. 字体交换导致的布局偏移 */
/* 使用 font-display: optional 或 swap + size-adjust */
@font-face {
  font-family: 'MyFont';
  src: url('/fonts/myfont.woff2') format('woff2');
  font-display: optional; /* 如果字体未加载完，用后备字体 */
  size-adjust: 105%;      /* 调整后备字体大小匹配 */
}

/* 3. 动态插入内容预留空间 */
.ad-slot {
  min-height: 250px; /* 广告位预留高度 */
}

/* 4. 避免 top/left 动画引起偏移 */
/* 用 transform 而非改变布局属性 */
.animate-in {
  animation: slideIn 0.3s ease-out;
}
@keyframes slideIn {
  from { transform: translateY(20px); opacity: 0; }
  to { transform: translateY(0); opacity: 1; }
}

4. 常见问题与坑点

SSR 一定能提升性能吗？ +

不一定。SSR 提升首屏渲染速度（FCP/LCP），但 TTFB 会增加（服务器渲染耗时）。如果服务端渲染慢，反而降低体验。SSR 适合内容密集型页面（SEO 需求），CSR 适合交互密集型应用。混合方案：SSR 首屏 + CSR 后续交互。

过度优化有什么问题？ +

① 过早优化浪费时间（先度量再优化）；② 代码可读性下降（过度内联、过度缓存）；③ 增加维护成本；④ 可能引入 Bug。原则：先确保正确性，再优化性能；先用工具定位瓶颈，再针对性优化。

🚫 不要忽视服务端性能

TTFB（首字节时间）是前端优化的基础。如果服务器响应慢（>1s），前端再怎么优化也无济于事。TTFB 优化：CDN、缓存、数据库优化、SSR 缓存、边缘计算。

1前端性能优化有哪些手段？
加载优化：代码分割、Tree-shaking、Gzip/Brotli、CDN、HTTP/2、预加载、懒加载、SSR/SSG、图片优化。运行时优化：防抖节流、虚拟列表、Web Worker、rAF、减少重排重绘、内存管理。感知优化：骨架屏、渐进加载、过渡动画。
2什么是 Core Web Vitals？
Google 定义的三个核心性能指标：LCP（最大内容绘制，衡量加载速度，好≤2.5s）、INP（交互到绘制延迟，衡量交互响应，好≤200ms）、CLS（累积布局偏移，衡量视觉稳定性，好≤0.1）。这些指标影响 Google 搜索排名。
